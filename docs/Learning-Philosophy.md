# Learning Philosophy

## Purpose

The goal of this project is to build a child's general problem-solving and reasoning capability, not merely improve performance on a particular type of math worksheet.

The central capability is the ability to face a problem that does **not** arrive with an obvious procedure attached and still make forward progress.

## The reasoning loop

The learner should gradually internalize a repeatable loop:

1. **Understand the problem.** What is happening? What is the problem actually asking?
2. **Notice what is known.** What facts, relationships, anchors, constraints, or familiar reference points might be useful?
3. **Build a possible path.** Choose a reasonable first step without needing certainty that it is the perfect one.
4. **Try the path.** Work forward and see what the approach produces.
5. **Check and learn.** Does the result make sense? Did the path get closer to the goal?
6. **Revise if needed.** Back up to the last useful point and try another route.

This is meant to model real-world problem solving, where the correct method is often not labeled in advance.

## Productive struggle

The learner should have enough difficulty to require real thought, but not so much that the experience becomes paralysis.

The design target is:

> **Protect the struggle, but prevent being completely stuck.**

Hints should therefore be progressive. Early hints should redirect attention rather than reveal a procedure. Stronger hints should appear only when necessary.

## Path before answer

The project deliberately emphasizes the reasoning path before the final answer.

The learner is encouraged to:
- explain what the problem asks;
- identify useful facts;
- show or draw a route;
- test an idea;
- then state the answer.

A correct answer without understanding is less valuable than a thoughtful, partially successful path that can be examined and improved.

## Multiple valid routes

Whenever a problem genuinely allows multiple solution paths, the material should make that visible.

After the learner completes a problem, an alternate route may be shown as another way to think—not as a correction of the learner's method.

This develops flexibility and helps prevent the belief that every problem has one hidden teacher-approved trick.

## Confidence as a learning objective

Confidence is not treated as a reward that comes only after mastery. It is itself part of the skill being developed.

The learner should repeatedly experience:

> “I may not know the answer yet, but I can find something useful, try a step, and keep going.”

Positive feedback should recognize specific thinking behaviors:
- finding an anchor;
- breaking a problem into parts;
- trying an idea;
- drawing a representation;
- checking a result;
- noticing something did not work;
- revising an approach;
- persisting thoughtfully.

The answer matters. The ability to keep thinking matters more.
