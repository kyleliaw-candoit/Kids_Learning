# Design Principles

These principles summarize the design choices made during the first five prototype missions and the reasoning behind them.

## 1. Keep computation light; make reasoning do the work

The math should generally be easy enough that calculation does not consume most of the learner's working memory.

The challenge should come from questions such as:
- What is being asked?
- Which known fact is useful?
- How can the problem be divided?
- Should I work forward or backward?
- What could I try first?

This prevents the project from becoming ordinary arithmetic practice.

## 2. Ask for the path before the answer

On the mission debrief, **Show Your Path** appears before **Your Answer**.

Why: page order communicates values. If the answer appears first, it subtly tells the learner that the result is the main event. Putting the path first reinforces that reasoning is the primary work and the answer follows from it.

## 3. Use progressive hints, not immediate instruction

Hints should form a ladder.

Typical progression:
1. direct attention to something potentially useful;
2. suggest an anchor or representation;
3. give a stronger structural nudge;
4. only near the end, make the route fairly explicit.

Why: a hint should restore forward movement without stealing the act of figuring something out.

## 4. Reward thinking behaviors rather than correctness alone

Gamification should recognize actions such as:
- “I found a clue.”
- “I tried a path.”
- “I broke it into parts.”
- “I checked my idea.”
- “I tried again.”

Why: rewarding only correct answers can make uncertainty feel like failure. Rewarding the process makes exploration safer.

## 5. Use a sidekick, not an all-knowing teacher

The mascot, Remy the Raccoon, is a curious thinking companion.

Remy should:
- wonder;
- notice;
- make expressive faces;
- encourage attempts;
- celebrate persistence;
- occasionally look puzzled.

Remy should not feel like an authority who already knows everything.

Why: the desired mental model is “we can figure this out,” not “the expert will show me the trick.”

## 6. Make the character playful and memorable

The learner responds strongly to silly cartoon characters, so Remy was deliberately revised from a calmer generic mascot into a more expressive, funky character.

The visual style was then simplified:
- fewer lines;
- flatter color areas;
- simpler shapes;
- strong facial expressions;
- clear silhouette.

Why: personality increases engagement, while simpler visual construction keeps the page readable and makes the character reusable.

## 7. Keep the page visually inviting but not babyish

The materials should feel playful for an elementary-school learner without resembling preschool worksheets.

Current direction:
- restrained color palette;
- clear writing space;
- modest header sizes;
- moderate problem-text size;
- smaller mascot footprint so the activity remains primary;
- playful mission language.

## 8. Treat paper as interactive

Paper is not considered a limitation.

The learner can:
- circle facts;
- draw;
- cross things out;
- flip to optional hints;
- compare alternate paths;
- physically control when help is revealed.

Why: the goal is to discover the right learning interaction before investing in an app.

## 9. Do not standardize too early

The first several problems are prototypes.

A master template should be extracted only after observing how the learner actually uses multiple missions.

Why: premature standardization risks making a polished system around assumptions that have not yet been tested.

## 10. One printable package per problem

Current production convention: one PDF per problem, with the grown-up guide included at the end.

Why: this reduces file clutter while keeping facilitation guidance attached to the activity.
